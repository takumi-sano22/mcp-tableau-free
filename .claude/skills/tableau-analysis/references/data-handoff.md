# データを Tableau へ渡す

## テーブルは long 形式で作る

Tableau は「1行1観測」の縦持ちを前提に集計・色分け・フィルタを組む。指標ごとに列を
増やした横持ちを渡すと、シートごとに列を選び直すことになり、軸を増やすたびに作り直しになる。

推奨する分け方（分析対象が「実行結果の集まり」の場合）:

| テーブル | 粒度 | 用途 |
| --- | --- | --- |
| `*_runs` | 1実行1行 | 実行のメタ情報（日時・条件・使ったモデル等） |
| `*_scores` | 実行 × 条件 × 指標 | 推移・比較の主データ |
| `*_metrics` | 実行 × 条件 × 指標 | スコア以外の数値（件数・比率） |
| `case_*` | 明細 × 指標 | 分布・内訳の掘り下げ |
| `*_targets` | 指標 | 基準線・目標値 |

**粒度の違うものを1テーブルに混ぜない。** 平均を取る対象（スコア）と合計を取る対象（件数）が
同じ列に入ると、シートの集計方法を間違えたときに黙って誤った数字が出る。やむを得ず混ぜる
場合は、区別する列（例: `axis_group`）を必ず持たせる。

## 比較できない行を混ぜない

評価基準・判定方法が途中で変わったデータを1本の折れ線にすると、変化に見えないものが
変化に見える。**比較可能な単位を列で明示する**（例: `judge_version` / `compare_group`）。
シート側ではその列でフィルタするか、パネルを分ける。

## 0 件を欠測にしない

「何件あったか」を数える指標は、**1 件も無かった組の行が生成されない**という落とし穴がある。
行が無いと Tableau では欠測になり、**「0 件まで減った」という改善が推移グラフに描けない**
（点が消えるだけで、減ったのか測っていないのか区別がつかない）。

明細から件数を集計するときは、**対象の直積を基準にしてゼロ行を明示的に作る**。直積の取り方は
「集計したい単位のうち、実際に測定が行われた組」にする。測っていない組まで 0 で埋めると、
今度は測っていないものを測ったように見せてしまう。

## 集計の前提を列で持つ

「有効な行だけで平均を出す」といった前提があるなら、除外条件を列にする（例: `evaluable`）。
Tableau 側でフィルタできるようになり、元のサマリと数字が一致するか検証できる。
**サマリ（集計済みの値）と明細の両方を入れて、突き合わせられるようにしておく。**

## CSV から .hyper へ

CSV のまま Tableau に読ませても動くが、型が推論任せになり数値が文字列に落ちることがある。
集計軸と並び順に使う列だけは型を明示して `.hyper` に入れる。

`scripts/build_hyper.py` を使う。型は各列の値から推論し、`types.json` を渡せばテーブル・列
単位で明示できる（text / int / double / timestamp）。CSV に無い列を指定した場合や未知の型名は
エラーになるので、定義とヘッダのずれはその場で分かる。

```bash
python scripts/build_hyper.py <csv_dir> <out.hyper>
```

要点:

- `tableauhyperapi` が要る（`pip install tableauhyperapi`。Linux wheel あり）
- `public` スキーマは新規ファイルにも既定で存在する。`create_schema` は失敗するので
  `create_schema_if_not_exists` を使う
- 空欄は `None`（NULL）にする。0 と欠測が混ざると集計が狂う
- 日時はタイムゾーンを決めて渡す（UTC のまま入れるか、読み手の時間帯へ寄せるか）

## Tableau は .hyper を排他する

**Tableau が開いている間、その `.hyper` は他プロセスから読めず、上書きもできない。**
MCP から中身を確認したい場合や、データを再生成したい場合に衝突する。

対処:

- **データの実体を2箇所に置く**。作業用（MCP から読む・再生成する）と、Tableau に渡す用
- あるいは `.twbx`（ワークブックとデータを固めた zip）にする。同梱されるので元ファイルの
  排他と無関係になる
- 更新が `Permission denied` になったら、まず Tableau が掴んでいないか疑う

## WSL から使う場合の置き場所

Tableau 本体が Windows 側にある場合、渡すファイルは Windows から見えるパスに要る。

- WSL のパスは `\\wsl.localhost\<distro>\home\...` で Windows から見える（`wslpath -w` で変換）
- ただしネットワークパス扱いになるため、**Windows のローカルディスクへコピーするほうが確実**
- 作業用の実体は WSL 側に残し、渡す用だけコピーする運用にすると排他を避けられる

## MCP で中身を確認する

Hyper を読む MCP（`tableau-local` 等）があれば、Tableau を開かずにテーブル一覧と先頭行を
確認できる。**生成直後にこれで確かめると、列名・型・行数の取り違えをその場で潰せる。**
このスキルと同じリポジトリ（mcp-tableau-free）に、ローカル `.hyper` 用の最小 MCP サーバが入っている。

確認する順:

1. ファイルが認識されるか（`list_hyper_files`）
2. テーブルが揃っているか（`list_hyper_tables`）
3. 列と値が意図どおりか（`preview_hyper_table`）

## 数字は必ず出どころと突き合わせる

抽出したテーブルの値が元データと一致するかを、**代表的な行で必ず確認する**。集計済みの
レポートが手元にあるなら、それと突き合わせる。差異が出たら、どちらが正かを一次データ
（生成元のファイル）で確かめる。ドキュメント側の転記ミスであることもある。
